#### ***4.1.2.1. Approaches Statements*** {#4.1.2.1.-approaches-statements}

* **Enfoque** APP-01: Domain-Driven Design (DDD)

* El sistema se organiza en Bounded Contexts independientes (IAM, Flota, Órdenes, Inventario FIFO, Facturación SUNAT, Telemetría IoT, Analítica), cada uno con modelo propio, lenguaje ubicuo y base de datos privada.

* **Drivers gobernados:** Drivers: US01, US02, US15, US25, QA-10, QA-11, CRN-1

* **Enfoque** APP-02: Attribute-Driven Design (ADD v3)

* Se aplica el proceso iterativo del SEI para guiar cada decisión a partir de requerimientos arquitectónicamente significativos (ASRs), evaluando conceptos de diseño y registrando ADRs.

* **Drivers gobernados:** Drivers: QA-01 al QA-12, CON-1 al CON-6

* **Enfoque** APP-03: Persistencia Políglota Descentralizada

* Cada microservicio gestiona su propio motor de base de datos: PostgreSQL 16 para datos transaccionales con RLS, TimescaleDB para series temporales de sensores, MongoDB para diagnósticos, ClickHouse para analítica y Redis para caché.

* **Drivers gobernados**: Drivers: QA-01, QA-02, QA-05, CRN-1

* **Enfoque** APP-04: Gestión de Código con GitFlow y Conventional Commits

* Se utiliza el flujo de ramas GitFlow (feature, develop, release, main, hotfix) con mensajes de commit estructurados por tipo y alcance, y versionamiento semántico formal (SemVer).

* **Drivers gobernados:** Drivers: QA-10, QA-11

* **Enfoque** APP-05: Infraestructura como Código (IaC) sobre Contenedores

* Los servicios se empaquetan en contenedores Docker y se orquestan mediante manifiestos reproducibles, asegurando coherencia entre entornos de desarrollo, pruebas y producción.

* **Drivers gobernados**: Drivers: CON-2, QA-03, CRN-3
