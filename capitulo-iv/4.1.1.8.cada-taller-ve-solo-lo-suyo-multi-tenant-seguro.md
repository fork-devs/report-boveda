#### ***4.1.1.8. Cada taller ve solo lo suyo (multi-tenant seguro)*** {#4.1.1.8.-cada-taller-ve-solo-lo-suyo-(multi-tenant-seguro)}

Ningún acceso a datos existirá sin identificador de taller verificado.

**Qué significa:** en SaaS varios talleres comparten plataforma con aislamiento. Modelos posibles: base por taller (más seguro, más caro), esquema por taller (intermedio) o todos juntos con columna tenant\_id \+ filtro automático (Seguridad a Nivel de Fila, Row-Level Security, RLS). La identidad viajará en Token Web JSON (JSON Web Token, JWT) con tenant\_id y roles, bajo OAuth 2.0 / OpenID Connect (OIDC), idealmente con segundo factor (Autenticación Multifactor, Multi-Factor Authentication, MFA), validado con llaves públicas (Juego de Llaves Web JSON, JSON Web Key Set, JWKS).

**Cómo lo usaremos:** el borde validará el token y propagará el tenant\_id; cada servicio y cada consulta lo exigirá. Empezaremos con aislamiento lógico riguroso \+ pruebas cruzadas entre tenants (tenant-cross) y dejaremos puerta a un plan premium aislado.
