### ***3.2.2. User Stories y criterios de aceptación***

| Epic / User Story ID | Título | Descripción | Criterios de Aceptación | Relacionado con (Epic ID) |
| ----- | ----- | ----- | ----- | ----- |
| **US01** | Registrar cliente y vehículo | Como gestor del taller, deseo registrar los datos del cliente y de su vehículo para reutilizarlos en las atenciones y mantener un historial único. | **CA1.** El registro solicita los datos obligatorios del cliente y la placa del vehículo antes de guardarse. **CA2.** Si la placa ya existe dentro del mismo taller, el sistema informa la coincidencia y permite seleccionar el registro existente en lugar de duplicarlo. **CA3.** El cliente y el vehículo quedan vinculados entre sí y disponibles para crear futuras órdenes de trabajo. | **EP01** |
| **US02** | Crear orden de trabajo | Como gestor del taller, deseo crear una orden de trabajo digital para centralizar el motivo de ingreso, el vehículo y la información inicial del servicio. | **CA1.** La orden recibe un identificador único y queda vinculada con un cliente y un vehículo registrados. **CA2.** El sistema exige el motivo de ingreso y la fecha de recepción antes de confirmar la orden. **CA3.** La orden se crea en estado abierto y registra la fecha y el usuario responsable de su creación. | **EP01** |
| **US03** | Actualizar tareas y estado de la orden | Como gestor o técnico mecánico, deseo actualizar las tareas y el estado de una orden para que el avance del servicio pueda consultarse sin recurrir a registros en papel. | **CA1.** Solo el gestor o el técnico asignado puede registrar tareas ejecutadas y cambiar el estado de la orden. **CA2.** Cada cambio conserva la fecha, la hora, el usuario responsable y el estado anterior. **CA3.** El sistema solo permite estados definidos dentro del flujo de atención y muestra el estado vigente en la consulta de la orden. | **EP01** |
| **US04** | Cerrar técnicamente una orden | Como técnico mecánico, deseo finalizar mi intervención en una orden para dejar registrado el diagnóstico confirmado y el trabajo realizado antes del cierre administrativo. | **CA1.** La orden solo puede finalizarse cuando contiene un diagnóstico confirmado y el detalle de las tareas realizadas. **CA2.** Al finalizar, el sistema registra al responsable y la fecha de cierre técnico, y bloquea nuevas modificaciones operativas. **CA3.** La reapertura solo puede realizarla un gestor autorizado, quien debe registrar el motivo; la acción queda en el historial. | **EP01** |
| **US05** | Vincular un escáner OBD-II | Como técnico mecánico, deseo vincular un escáner OBD-II compatible con el vehículo atendido para iniciar una sesión de diagnóstico desde la orden de trabajo. | **CA1.** El sistema permite detectar o seleccionar un dispositivo OBD-II compatible sin depender de una marca específica. **CA2.** La conexión se valida antes de asociar la sesión con el vehículo y la orden seleccionados. **CA3.** Si la conexión falla, el sistema informa el problema y no registra lecturas incompletas como una sesión válida. | **EP02** |
| **US06** | Registrar códigos DTC y parámetros PID | Como técnico mecánico, deseo registrar los códigos DTC y los parámetros PID disponibles para contar con datos telemétricos asociados al diagnóstico del vehículo. | **CA1.** Cada lectura queda vinculada con la sesión, la orden y el vehículo correctos. **CA2.** Los códigos DTC y los parámetros PID conservan su valor, unidad disponible y fecha de captura. **CA3.** Una nueva lectura no reemplaza las lecturas anteriores y puede sincronizarse sin generar registros duplicados. | **EP02** |
| **US07** | Consultar lecturas y validar el diagnóstico | Como técnico mecánico, deseo revisar las lecturas telemétricas y registrar mi diagnóstico final para utilizar los datos del vehículo como apoyo sin sustituir mi criterio profesional. | **CA1.** La consulta muestra los códigos DTC y parámetros PID asociados a la orden, ordenados por fecha de lectura. **CA2.** La interfaz diferencia claramente los datos telemétricos y recomendaciones del diagnóstico confirmado por el técnico. **CA3.** La confirmación registra el diagnóstico final, el técnico responsable y la fecha; ninguna alerta se marca automáticamente como diagnóstico definitivo. | **EP02** |
| **US08** | Generar una alerta preventiva | Como gestor del taller, deseo que el sistema genere alertas a partir de eventos telemétricos para identificar vehículos que requieren una revisión preventiva. | **CA1.** Cuando una regla configurada se cumple, la alerta identifica el vehículo, la causa, la fecha y el nivel de atención. **CA2.** Si la condición no cumple la regla, el sistema no crea una alerta preventiva. **CA3.** Las repeticiones de un mismo evento activo se agregan al historial de la alerta y no generan duplicados independientes. | **EP03** |
| **US09** | Gestionar alertas preventivas | Como gestor del taller, deseo revisar y actualizar las alertas preventivas para priorizar el seguimiento de los vehículos atendidos. | **CA1.** El panel permite filtrar alertas por estado, fecha, vehículo y nivel de atención. **CA2.** El gestor puede cambiar una alerta entre pendiente, en revisión, atendida o descartada; el descarte exige un motivo. **CA3.** Cada cambio de estado conserva la fecha y el usuario responsable en el historial de la alerta. | **EP03** |
| **US10** | Programar un servicio desde una alerta | Como gestor del taller, deseo convertir una alerta preventiva en una cita de servicio para atender al vehículo antes de que la falla se agrave. | **CA1.** La cita se crea con el vehículo y el motivo de la alerta previamente cargados. **CA2.** El sistema valida la disponibilidad seleccionada antes de confirmar la programación. **CA3.** Al confirmarse la cita, la alerta conserva el vínculo con la programación; si el registro falla, su estado no cambia. | **EP03** |
| **US11** | Capturar evidencia fotográfica | Como técnico mecánico, deseo tomar fotografías desde la aplicación móvil para registrar el estado del vehículo durante la recepción, la reparación y la entrega. | **CA1.** Cada fotografía queda asociada a una orden y a una etapa: recepción, reparación o entrega. **CA2.** La evidencia conserva la fecha, la hora y el usuario que realizó la captura. **CA3.** Una fotografía confirmada no puede reemplazarse ni eliminarse; cuando no hay conexión queda marcada para sincronización posterior. | **EP04** |
| **US12** | Consultar la línea de tiempo de evidencias | Como gestor del taller, deseo consultar las evidencias fotográficas en orden cronológico para responder a reclamos y verificar el estado documentado del vehículo. | **CA1.** La consulta agrupa las fotografías por orden y las presenta cronológicamente con su etapa de captura. **CA2.** El sistema permite abrir la evidencia original sin alterar el archivo registrado. **CA3.** Solo los usuarios autorizados del mismo taller pueden consultar las evidencias de la orden. | **EP04** |
| **US13** | Registrar lotes de repuestos | Como gestor del taller, deseo registrar el ingreso de repuestos por lote para conocer la cantidad y el costo real de cada compra. | **CA1.** El lote registra el repuesto, la cantidad, el costo unitario, la fecha de ingreso y el proveedor. **CA2.** El sistema rechaza cantidades o costos negativos y exige los datos obligatorios antes de guardar. **CA3.** Cada lote recibe un identificador propio y actualiza las existencias del repuesto dentro del taller. | **EP05** |
| **US14** | Consultar existencias por lote | Como gestor del taller, deseo consultar el stock total y los lotes disponibles de cada repuesto para decidir si una reparación puede atenderse sin realizar una compra adicional. | **CA1.** La consulta muestra la existencia total y el saldo de cada lote ordenado desde el más antiguo. **CA2.** El gestor puede buscar el repuesto por su nombre o código y ver la fecha y el costo de los lotes disponibles. **CA3.** La información corresponde únicamente al inventario del taller del usuario y refleja los consumos confirmados. | **EP05** |
| **US15** | Consumir repuestos mediante FIFO | Como gestor del taller, deseo asignar repuestos a una orden aplicando FIFO para descontar primero el lote disponible más antiguo y conservar el costo real del consumo. | **CA1.** El sistema descuenta la cantidad solicitada empezando por el lote con fecha de ingreso más antigua. **CA2.** Si la cantidad requiere más de un lote, cada fracción y su costo quedan vinculados con la misma orden. **CA3.** Si el stock es insuficiente, el consumo no se confirma y el sistema informa la cantidad faltante. **CA4.** Una reversión autorizada repone las cantidades en los lotes de origen y deja registro del responsable y el motivo. | **EP05** |
| **US16** | Consultar costo y margen de la orden | Como gestor del taller, deseo consultar el costo y el margen de una orden para conocer la rentabilidad real del servicio antes de liquidarlo. | **CA1.** El costo de repuestos se calcula con los lotes realmente consumidos y se presenta separado del costo de mano de obra registrado. **CA2.** El margen se calcula usando el importe aprobado para la orden y los costos disponibles; si falta un costo obligatorio, el resultado se muestra como incompleto. **CA3.** Durante la atención, el cálculo se actualiza con cada cambio; al cerrar la orden se conserva el resumen utilizado para la liquidación. | **EP05** |
| **US17** | Consultar disponibilidad de técnicos y bahías | Como gestor del taller, deseo consultar la disponibilidad de técnicos y bahías para elegir un horario que pueda atenderse con los recursos existentes. | **CA1.** La agenda muestra por fecha los periodos disponibles y ocupados de cada técnico y bahía. **CA2.** La disponibilidad considera las citas y órdenes ya asignadas dentro del mismo taller. **CA3.** Al abrir una ocupación, el gestor puede identificar la cita u orden que reserva el recurso. | **EP06** |
| **US18** | Programar o reprogramar un servicio | Como gestor del taller, deseo programar o reprogramar un servicio para organizar la atención del vehículo y mantener actualizada la agenda. | **CA1.** La programación registra el vehículo, el tipo de servicio, la fecha, la hora y la duración prevista. **CA2.** El sistema no confirma un horario que se superpone con una reserva vigente de los recursos seleccionados. **CA3.** La reprogramación conserva el horario anterior en el historial y la cancelación libera los recursos reservados. | **EP06** |
| **US19** | Asignar técnico y bahía | Como gestor del taller, deseo asignar una orden a un técnico y una bahía disponibles para distribuir la carga de trabajo sin generar cruces operativos. | **CA1.** La asignación solo puede confirmarse si el técnico y la bahía están disponibles para el periodo de la orden. **CA2.** La orden registra los recursos asignados, la fecha y el gestor que realizó la acción. **CA3.** Una reasignación conserva el historial y la nueva orden aparece en la vista de trabajo del técnico seleccionado. | **EP06** |
| **US20** | Registrar tiempo por tarea | Como técnico mecánico, deseo iniciar, pausar, reanudar y finalizar el tiempo de una tarea para registrar la mano de obra efectiva dedicada a la orden. | **CA1.** El cronómetro se vincula con una tarea, una orden y el técnico que la ejecuta. **CA2.** Un técnico no puede mantener dos cronómetros activos al mismo tiempo. **CA3.** El tiempo efectivo excluye las pausas y conserva los momentos de inicio, reanudación y finalización, incluso si fueron registrados sin conexión. | **EP07** |
| **US21** | Validar proximidad y revisar tiempos | Como gestor del taller, deseo revisar los tiempos registrados y su validación de proximidad para comparar la duración prevista con la duración real de cada orden. | **CA1.** Cuando el dispositivo dispone de permiso y ubicación, el inicio y el cierre del cronómetro registran si ocurrieron dentro de la geocerca del taller. **CA2.** Si la ubicación no está disponible, el registro de tiempo se conserva como pendiente o no verificado y no se descarta el trabajo realizado. **CA3.** El gestor puede consultar el tiempo previsto, el tiempo efectivo y su diferencia por orden y por técnico. **CA4.** El técnico puede revisar sus propios registros, y toda corrección autorizada conserva el valor anterior, el motivo y el responsable. | **EP07** |
| **US22** | Trabajar sin conexión y sincronizar | Como técnico mecánico, deseo continuar con las operaciones principales de mi orden cuando no hay internet para no interrumpir el trabajo en la bahía. | **CA1.** Sin conexión, el técnico puede consultar las órdenes previamente cargadas y registrar tareas, estados, evidencias, tiempos y lecturas permitidas. **CA2.** La aplicación identifica de forma visible los registros pendientes de sincronización. **CA3.** Al recuperar la conexión, los datos se sincronizan una sola vez y quedan vinculados con la orden correcta. **CA4.** Si existe un conflicto, el sistema conserva ambas versiones y solicita una resolución autorizada sin perder el registro local. | **EP08** |
| **US23** | Acceder según el rol y el taller | Como gestor o técnico mecánico, deseo acceder a las funciones correspondientes a mi rol para trabajar con la información autorizada de mi propio taller. | **CA1.** El usuario debe identificarse y tener una cuenta activa asociada con un taller antes de acceder. **CA2.** El gestor accede a las funciones administrativas y el técnico a las funciones operativas de las órdenes que le corresponden. **CA3.** El sistema impide consultar o modificar información de otro taller, incluso cuando se intenta acceder mediante una dirección directa. **CA4.** La vista móvil del técnico prioriza las acciones de trabajo con controles legibles y evita mostrar módulos administrativos innecesarios. | **EP08** |
| **US24** | Elaborar y aprobar un presupuesto | Como gestor del taller, deseo preparar alternativas de presupuesto y registrar la opción aprobada para acordar con el cliente el alcance y el costo de la reparación. | **CA1.** El presupuesto puede incluir alternativas de repuestos por nivel de calidad, mano de obra, impuestos y total. **CA2.** La opción seleccionada queda vinculada con la orden junto con la fecha y el medio de aprobación registrado. **CA3.** Un presupuesto aprobado no se sobrescribe; cualquier cambio crea una nueva versión y conserva la anterior. | **EP09** |
| **US25** | Emitir comprobante electrónico | Como gestor del taller, deseo emitir el comprobante electrónico desde una orden liquidada para evitar volver a digitar la información y completar el cierre administrativo. | **CA1.** La emisión solo se habilita para una orden con cierre técnico, presupuesto aprobado y datos fiscales requeridos. **CA2.** El gestor puede seleccionar el tipo de comprobante permitido y los importes coinciden con la liquidación de la orden. **CA3.** El sistema registra el estado, la fecha y la respuesta recibida del servicio de facturación electrónica. **CA4.** Si la emisión es rechazada, la orden no se marca como facturada y el gestor puede corregir los datos y volver a intentarlo. | **EP09** |
