### ***2.3.2. User task matrix*** {#2.3.2.-user-task-matrix}

La User Task Matrix organiza las actividades cotidianas que realizan los usuarios del taller para cumplir sus objetivos de trabajo. Siguiendo las indicaciones del statement, estas tareas representan procesos operativos del negocio automotriz y no funciones del sistema de software, ya que los talleres las llevan a cabo de forma manual o empírica antes de contar con DriveOS.

A continuación se evalúa la frecuencia y la importancia de cada tarea para los dos perfiles principales identificados: Roberto García (dueño y gestor del taller) y Kevin Ramírez (técnico mecánico en bahía):

**Análisis de Tareas y Diferencias entre Roles:**

**Coincidencias:** Puntos de contacto operativos: Las tareas de inspección inicial (TK02) y uso de repuestos (TK06) son momentos clave donde el gestor y el mecánico deben coordinar. Cualquier desfase en la cantidad o costo de repuestos genera pérdidas directas para el taller.

**Divergencias:** Diferencias de enfoque: El gestor se concentra en el control administrativo, la rentabilidad por orden y la facturación ante SUNAT (TK04, TK12, TK13). El técnico mecánico necesita registrar su trabajo rápido en bahía sin perder tiempo escribiendo en papel ni lidiando con menús complejos (TK03, TK07, TK09).

**Conclusión:** Decisión de diseño: Esta marcada diferencia justifica que DriveOS ofrezca dos interfaces independientes: un panel web administrativo para el gestor y una aplicación móvil ligera y Offline-First para el técnico en fosa.
