### ***5.1.3. Pattern Based Custom Software Library*** {#5.1.3.-pattern-based-custom-software-library}

Para evitar la duplicación de código transversal (cross-cutting concerns), estandarizar la seguridad y acelerar el desarrollo consistente entre los distintos microservicios políglotas, el equipo de ingeniería de ForkDevs diseñó e implementó un conjunto de Bibliotecas de Software Personalizadas (Custom Software Libraries / Shared Kernels). Cada una de estas librerías cuenta con su propio repositorio, ciclo de versionamiento semántico y suite de pruebas unitarias independiente:

* 1\. drivers-commons-security (Java Starter & Go Package): Encapsula la lógica de validación de tokens criptográficos JWT emitidos por Keycloak bajo el estándar OIDC (OpenID Connect) con llaves asimétricas RS256. Proporciona filtros de seguridad listos para usar que extraen automáticamente el tenant\_id, el user\_id y los roles RBAC (ROLE GESTOR TALLER, ROLE TÉCNICO MECÁNICO), inyectándose en el contexto de ejecución del hilo (SecurityContextHolder en Spring Boot y context.Context en Go). Cuenta con pruebas unitarias que validan la expiración de tokens, firmas manipuladas y revocación de permisos.  
* 2\. drivers-commons-events (Java / Go / Python): Define los esquemas canónicos y los contratos de eventos de dominio distribuidos siguiendo la especificación Cloud Events 1.0. Provee serializadores y deserializadores fuertemente tipados para eventos como Work Order CreateEvent, Telemetry Reading ReceivedEvent, StockReservedEvent y Fiscal Invoice Emitted Event, incluyendo metadatos de trazabilidad distribuida (transparent de Open Telemetry). Su suite de pruebas unitarias garantiza la compatibilidad binaria entre lenguajes.  
* 3\. drivers-commons-outbox (Java Spring Boot Starter): Librería personalizada que implementa el motor de Transactional Outbox de manera transparente para los microservicios. Expone la entidad de auditoría Outbox EventEntity, interceptores automáticos de eventos de dominio mediante anotaciones (@PublishDomainEvent) y un procesador asíncrono con bloqueo distribuido ligero basado en PostgreSQL advisory locks para garantizar que los eventos se publiquen a Kafka en estricto orden cronológico.  
* 4\. drivers-commons-errors (Java, Go, Python): Estandariza el manejo global de excepciones de acuerdo con la norma internacional IETF RFC 7807 (Problem Details for HTTP APIs). Transforma automáticamente cualquier error de dominio o validación en una respuesta JSON estructurada con campos type, title, status, detail, instance y timestamp. Garantiza mediante pruebas automatizadas que ninguna excepción no controlada exponga trazas internas del servidor (stack traces) hacia el cliente.  
* 5\. drivers-commons-multitenancy (Java Spring Data / Hibernate): Extensión de persistencia que intercepta cada conexión obtenida del pool HikariCP e inyecta la variable de sesión PostgreSQL (SET LOCAL app.current tenant\_id \= ?) de forma automática a partir del contexto del hilo. Su suite de pruebas utiliza Test Containers PostgreSQL para verificar que ninguna consulta JPA o SQL nativo omita la cláusula de seguridad multi-tenant.
