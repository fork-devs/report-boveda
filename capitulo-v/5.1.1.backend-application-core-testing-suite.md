### ***5.1.1. Backend Application Core Testing Suite*** {#5.1.1.-backend-application-core-testing-suite}

La suite de pruebas del backend de DriveOS sigue la pirámide de testing en cuatro niveles, balanceando cobertura y velocidad de ejecución en CI/CD.  
1\. Pruebas unitarias de dominio:  
Se ejecutan en milisegundos sin dependencias externas. Cubren las invariantes de negocio de los agregados raíz (WorkOrder, KardexLot, FiscalInvoice) y los Value Objects inmutables (DtcCode, PidParameter, Money, VinNumber, RucNumber). Se verifican el costeo FIFO, las transiciones de la máquina de estados de órdenes de trabajo y la emisión de eventos de dominio como WorkOrderCreated, StockReserved y FiscalInvoiceEmitted.  
2\. Pruebas de casos de uso y aplicación  
Verifican la orquestación de Command Handlers usando mocks y stubs para aislar repositorios y publicadores de eventos. Ante un caso de uso como LiquidateWorkOrder o ConsumeStockFifo, se comprueba que se apliquen las políticas de seguridad, se registre el evento en la tabla Outbox y se coordine la transacción dentro del contexto local.  
3\. Pruebas de integración y persistencia  
Corren contra instancias efímeras de PostgreSQL, TimescaleDB, Redis y Kafka gestionadas por Testcontainers. Validan que las consultas JPQL y SQL nativas, las políticas de Row-Level Security para aislamiento multi-tenant, el bloqueo pesimista y optimista en la reserva de repuestos, y la serialización de eventos en Kafka se comporten igual que en producción.  
4\. Pruebas de contratos de API y controladores  
Validan los endpoints REST con MockMvc y WebTestClient. Se comprueba el mapeo de DTOs a comandos, la validación de entrada con Bean Validation, Pydantic o Go Validator según el stack, la generación de contratos OpenAPI 3.0 y el formato de errores bajo RFC 7807\.
